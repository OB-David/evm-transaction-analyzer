# 调用树展示重构方案

## 目标

将现有静态时序图替换为前端动态渲染的**可折叠调用树**。重点优化展示和交互，尽量保留现有后端分析、函数签名查询、calldata 切片以及 JSON 产物。

调用树从左到右表示调用深度，同一父调用的子节点从上到下严格按照 `entry_step` 执行顺序排列。每个节点代表一次完整调用周期，即从 `CALL / STATICCALL / DELEGATECALL / CREATE` 等入口到对应的 `RETURN / REVERT / STOP` 等退出。

## 数据兼容

- 继续读取现有 `trace_sequence_calldata_mapping.json` 和 `legend.json`，不重新计算函数签名或 calldata。
- 前端根据 `entry_step / exit_step` 的区间包含关系建立父子关系、深度和后代数量；`call_id` 继续作为选择与折叠的稳定标识。
- 保留现有 JSON 字段和生成流程。第一阶段不修改 `backend/utils/sequence_diagram.py`；若真实数据出现名称冲突，再以可选字段方式补充地址和父调用 ID，不破坏旧产物。
- 新前端不再依赖 `trace_sequence.svg` 展示，但后端暂时继续生成该文件，便于兼容和回退。

## 节点与颜色

- 同一调用周期独立成节点；同一合约被多次调用时节点独立，但颜色保持一致。
- 颜色直接复用 `legend.json` 的合约颜色，并通过 `visualTheme.ts` 的 `getFillColorForColor` 和 `getDarkAccentForColor` 转换，保证与 Token Flow、CFG 一致。
- `legend.erc20_tokens` 中的 Token 合约使用椭圆形；普通合约使用矩形。虚拟交易根节点若能匹配用户地址则使用菱形。
- 节点显示调用编号、合约名、主要函数候选、入口类型、退出状态和 step 区间；`REVERT` 等异常同时使用文字和边框强调，不改变合约本身的统一填充色。
- `DELEGATECALL / CALLCODE` 使用虚线连接，其他调用使用实线，边上保留入口操作文字。

## 折叠与详情

- 节点折叠表示折叠该调用的完整生命周期，隐藏全部后代，并显示隐藏调用数量；支持单节点、全部以及按深度展开。
- 内容超出面板时提供水平和垂直滚动，不缩放文字和节点，也不启用滚轮缩放。
- 点击节点在图内显示详情浮窗；折叠按钮与节点选择分离，避免误操作。
- `Probable signatures` 默认显示后端排序后的首选名称；点击标题展开或收起全部候选，保持后端返回顺序。
- `Calldata` 默认显示 selector 和切片数量；点击标题展开或收起 `calldata` 数组中的全部 active slices，每个切片独立显示，不擅自拼接为完整 ABI 参数。
- 浮窗限制在图区域内，内容过长时仅浮窗内部滚动；切换节点时重置两个详情区的展开状态。

## 前端改造范围

- 以 `frontend/src/components/SequencePanel.vue` 为主要改造点，移除 PlantUML SVG 注入和 `d3-zoom`，改为 Vue 计算布局和原生 SVG 渲染调用树。
- 保留现有 `txHash`、`isAnalyzing`、`selectedStepRange` 属性及 `sequence-select` 事件，使节点选择仍可按 entry/exit step 联动 CFG。
- 保留 `.sequence-panel` 和 `.graph-viewport`，兼容现有页面布局与 SVG 导出；面板标题和导出名称改为 Call Tree。
- `frontend/src/api/analyze.ts` 只增加调用树所需的前端派生类型，不改变接口地址和现有产物格式。
- 大交易默认折叠到有限深度；布局仅处理当前可见节点，折叠后同步移除不可见节点和连接线。

## 验收标准

- 父子关系和同级上下顺序与真实执行顺序一致，同一合约的多次调用可分别折叠。
- 同一合约在调用树、Token Flow 和 CFG 中颜色一致；Token 节点为椭圆形。
- 折叠后所有后代节点和边均消失，隐藏数量准确，展开后顺序不变化。
- 函数候选与 calldata 切片可以独立展开、收起，数据与现有 JSON 完全一致。
- 节点选择继续联动 CFG，详情浮窗不越出图区域，水平和垂直滚动正常。
- `npm run build` 通过，并使用小型、深层、重复调用、Token 调用、REVERT 和大规模交易进行浏览器验证。
